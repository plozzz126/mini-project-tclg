# Ошибки ИИ-ассистента

Три места, где ответ ИИ оказался неверным и проверка в Network или тестах это показала.

## 1. «`/artworks?ids=` возвращает работы в том же порядке»

**Что предложил ИИ:** на странице `/expo/view` выводить `response.data` как есть.

**Как нашёл ошибку:** запрос `/artworks?ids=656,2990,99999999,21177` во вкладке Network вернул
`656, 21177, 2990`. Порядок другой, а несуществующий id `99999999` просто пропал, без ошибки.

**Исправление:** функция `orderByIds(artworks, ids)` раскладывает ответ по порядку из ссылки
и пропускает ненайденные. Есть тест на этот случай, а на странице пишется, сколько работ не нашлось.

## 2. «Последняя страница = `pagination.total_pages`»

**Что предложил ИИ:** кнопку «Следующая страница» отключать на `total_pages` (для `cats` это 22 230).

**Как нашёл ошибку:** `?page=420&limit=24` вернул `403 {"error":"Invalid number of results"}`.
API отдаёт не больше 10 000 результатов.

**Исправление:** `maxPage(total, limit) = min(ceil(total/limit), floor(10000/limit))`.
Кроме того, номер страницы, вписанный в адрес вручную (`/?page=999`), ограничивается тем же пределом.

## 3. «Фильтровать по цвету на клиенте и `color.h` всегда есть»

**Что предложил ИИ:** отфильтровать полученные 24 работы через `hueBucket(art.color)`.

**Как нашёл ошибку:** во-первых, у работы 21177 `color: null`, и код `color.h` упал бы.
Во-вторых, при фильтре на клиенте на странице оставалось 2–3 работы из 24, а «Найдено» и
`maxPage` показывали число без учёта фильтра.

**Исправление:** `hueBucket(null)` → `null`. Сам фильтр перенесён на сервер: запрос
`params={"q":…,"query":{"bool":{"filter":[…диапазоны color.h/color.s…]}}}`
использует те же границы, что `hueBucket`. Для красного это два диапазона: 0–14 и 345–359.
